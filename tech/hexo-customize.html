页面载入动画速度

v8 不再使用 anime.js，动画序列改由 motion.js 中的 integrator 调度。文章列表默认使用 overlap: 100 错峰启动；把它改为 200（与默认 motion.duration 相同），就能让列表中的动画同时启动，减少逐项出现的等待感。当前主题已应用此修改。

overlap 控制的是动画项的启动间隔，不是单项动画的播放时长。单项视觉动画的时长由 Animate.css 控制；如果要缩短淡入等效果本身，还需要调整 Animate.css 的动画时长。

图片延迟加载（lazyload）

lazyload就是延迟加载，只有在看到图片的时候才加载，从而加快网页载入速度。

注：构建仍会显示 NexT 关于 lazyload 已弃用的警告，但当前实现有效

在 next 主题的 _config.yml 中启用 lazyload。当前实现会在 Markdown 图片转成 HTML 时处理文章和独立页面中的图片。

需要排除的图片可在 lazyload_exclude 中填写其 src 的一段文本；匹配是逐张图片进行的，不会因为某张图片命中就跳过整篇文章。比如 osu-sig 会让 About 页面上的 osu 统计图片保持原样。

渲染引擎（renderer）

把 hexo 自带的 hexo-renderer-marked 卸载了，现在使用的是 hexo-renderer-markdown-it-plus

配置如下所示：

typographer 这个功能是默认开启的，会在渲染过程中，自动把所有的英语引号全部换成中文引号。具体解释可以看 6.4.0版本之后的两个问题。

可以把下面两行复制到文章中进行测试，如果左右渲染出来一样，就是被自动替换了。

'（U+0027） ---> ’（U+2019）

"（U+0022） ---> “（U+201C） + ”（U+201D）

所以只需要 typographer: false 就能禁用这个坑爹的功能

公式显示

直接使用 katex，体积小，而且支持公式的自适应换行，安装方法见这篇官方教程：Math Equations | NexT。

hexo 自带的renderer 不支持 katex，所以我安装的是升级版 hexo-renderer-markdown-it-plus。
